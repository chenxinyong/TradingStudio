- C++/CLI 封装或 C# 桥接层转换时丢失状态。
- 内部订单状态枚举与 CTP 枚举值不一致。

## 5\. 推荐的 CTP 状态映射

不要让 CTP 枚举直接污染 Domain。

应该：

```
CTP OrderStatus
       ↓
CtpOrderStatusMapper
       ↓
TradingStudio.OrderStatus
```

例如：

```
public static class CtpOrderStatusMapper
{
    public static OrderStatus Map(
        CtpOrderStatus status,
        CtpOrderSubmitStatus submitStatus)
    {
        return status switch
        {
            CtpOrderStatus.AllTraded
                => OrderStatus.Filled,

            CtpOrderStatus.PartTradedQueueing
                => OrderStatus.PartiallyFilled,

            CtpOrderStatus.NoTradeQueueing
                => OrderStatus.Accepted,

            CtpOrderStatus.Canceled
                => OrderStatus.Cancelled,

            _ => MapSubmitStatus(submitStatus)
        };
    }

    private static OrderStatus MapSubmitStatus(
        CtpOrderSubmitStatus status)
    {
        return status switch
        {
            CtpOrderSubmitStatus.InsertSubmitted
                => OrderStatus.Submitted,

            CtpOrderSubmitStatus.InsertRejected
                => OrderStatus.Rejected,

            _ => OrderStatus.Unknown
        };
    }
}
```

## Order

```
public sealed class Order
{
    public Guid Id { get; init; }

    public string StrategyId { get; init; } = null!;

    public string InstrumentId { get; init; } = null!;

    public OrderSide Side { get; init; }

    public OffsetFlag Offset { get; init; }

    public int Quantity { get; init; }

    public int FilledQuantity { get; private set; }

    public decimal LimitPrice { get; init; }

    public OrderStatus Status { get; private set; }

    public string? OrderRef { get; init; }

    public string? OrderSysId { get; private set; }

    public void ApplyTrade(int quantity)
    {
        if (quantity <= 0)
            throw new ArgumentOutOfRangeException(nameof(quantity));

        FilledQuantity += quantity;

        Status =
            FilledQuantity >= Quantity
                ? OrderStatus.Filled
                : OrderStatus.PartiallyFilled;
    }
}
```

这里有一个非常重要的设计：

> **Order 的 FilledQuantity 必须由成交事实驱动，而不是由 `OnRtnOrder` 的某一次回报直接覆盖。**

public sealed class OrderStateMachine : IOrderStateMachine
{
    public Order ApplyOrderUpdate(
        Order order,
        OrderUpdate update)
    {
        if (update.OrderSysId != order.OrderSysId)
            throw new InvalidOperationException(
                "Order identity mismatch.");

        return order.WithStatus(
            update.Status,
            update.FilledQuantity);
    }

    public Order ApplyTrade(
        Order order,
        Trade trade)

        return order.ApplyTrade(trade.Quantity);
    }
}

## 三十五、特别值得注意的一点

你的 README 其实已经明确写出了系统设计原则：

> 风控必须在 CTP 前；Order/Trade 全部事件必须可回放；合约规格必须数据驱动。 [^11]

而源码现在最大的问题恰恰是：

```
CTP 原始事实
      ↓
CtpTraderBridge
      ↓
OrderEvent
      ↓
信息丢失
```

尤其是：

```
TradeId
OffsetFlag
OrderSysId
StrategyId
NativeStatus
```

被丢掉以后，再漂亮的 `PortfolioManager` 都只能“猜”。

所以我认为 TradingStudio 当前真正应该进行的架构升级不是再加一个 `RiskRule` ，而是：

```
CTP FACTS
               │
     ┌─────────┴─────────┐
     ↓                   ↓
CtpOrderEvent       CtpTradeEvent
     │                   │
     └─────────┬─────────┘
               ↓
         Event Normalizer
               ↓
         OrderStateMachine
               ↓
      ┌────────┼─────────┐
      ↓        ↓         ↓
    Order     Trade   Reconcile
               │
               ↓
         PositionReducer
               │
               ↓
         AccountLedger
               │
               ↓
      Account / Strategy
         Snapshots
```

这一步完成后，你的 **CTP → Order → Risk → Trade → Position → Equity → Strategy** 才真正形成可验证的实盘闭环。
