# 05 - 缠论买卖点层 alpha 验证报告

> **日期**：2026-09-03
> **状态**：已验证，结论为负（买卖点层无正 alpha）
> **对应 spec**：[04-quant-spec.md](04-quant-spec.md) §9.3「单品种 + 单级别 → 夏普 > 0？」

---

## 1. 验证目的

按 spec §9.3 的验收标准，回答一个核心问题：

> **缠论的买卖点（B1/B2/B3/S1/S2/S3）作为交易信号，在单品种 + 单级别上有没有正 alpha？**

- 一买/一卖（B1/S1）：趋势背驰后的第一类买卖点
- 二买/二卖（B2/S2）：背驰后的回抽确认
- 三买/三卖（B3/S3）：中枢突破后的回抽不入中枢

---

## 2. 验证方法

| 项 | 配置 |
|----|------|
| 策略类 | `ChanLunSignalStrategy`（独立策略，SignalGenerator 信号驱动，无前视） |
| 无前视保证 | 信号以 `ConfirmEnd`（确认笔完成时间）为最早可交易时间戳，入场用当前 bar 收盘价 |
| 出场 | 反向买卖点反手 + ATR 追踪止损（StopAtrMult=2.0） |
| 数据 | DuckDB 历史库，1min 聚合 15min，连续主力合约 |
| 品种 | SA 纯碱（郑商所，宽幅震荡）、RB 螺纹钢（上期所，2020 翻倍行情） |
| 区间 | 2021-06-01 起（SA/RB 数据起点 2020-01，预热后正式交易） |
| 资金 | 100 万，单笔风险 2% |

---

## 3. 验证结果

### 3.1 三买卖点（B3/S3）—— 明确负 alpha

| 品种 | 周期 | 交易笔数 | 胜率 | 净盈亏 | 出场 |
|------|------|---------|------|--------|------|
| SA 纯碱 | 15min | 19 | 10.5% | **-33.9 万（-28.9%）** | 全部 ATR_SL |
| RB 螺纹钢 | 15min | 43 | 7.0% | **-18.8 万（-18.9%）** | 全部 ATR_SL |

两个品种一致负，且逻辑自洽：**三买卖点本质是「中枢突破后的追涨/杀跌」**，在震荡或趋势不明时反复被止损。结论可靠。

### 3.2 背驰买卖点（B1/B2/S1/S2）—— 被方法论缺陷卡死

背驰检测依赖 `ClassifyTrend` 返回趋势（UP/DOWN），两种趋势定义的结果：

| 趋势定义 | 结果 |
|----------|------|
| **spec §4.3 原文**（相邻中枢完全互不重叠） | 所有品种永远判 `CONSOLIDATION`，**背驰=0**，B1/B2/S1/S2 全部从未触发 |
| **放宽**（中枢重心 Zz 移动方向计数） | 背驰触发了，但**全局只判一个方向**（RB 6 年被整体判 UP），B1/B2 仍=0，只有 S1/S2 顶背驰做空 |

放宽后的 RB 结果：

| 交易区间 | 交易笔数 | 胜率 | 净盈亏 |
|----------|---------|------|--------|
| 全时段 2021-06+ | 26 | 7.7% | **-31.7 万（-28.8%）** |
| 仅下跌段 2024+ | 38 | 13.2% | **+4.3 万（+4.7%）** |

「+4.7%」看似转正，实为**「全局判 UP + 恰好遇到 2024-2026 下跌段」的巧合**：全局分类把 6 年整体判成上涨趋势，只发出顶背驰做空信号，而这段时间恰好下跌，做空才勉强转正。胜率仅 13.2%、回撤 12.8%，且依赖全局方向恰好与局部走势相反，不构成稳健 alpha。

---

## 4. 根因分析

### 4.1 背驰为何在严格定义下永远 = 0

spec §4.2 的中枢重叠合并用 `Zd=Min / Zg=Max`（合并后范围**膨胀**），而 §4.3 的趋势分类要求相邻中枢**完全互不重叠**（`zs2.Zd > zs1.Zg` 才判上移）。

两个规则叠加的结果：分钟级（15min）数据中，相邻中枢几乎必然有次级别接触 → 一旦重叠就短路判 `CONSOLIDATION`。即使 RB 从 3100 涨到 6204（翻倍），也被判成盘整。**这不是「没有趋势」，而是分类器判定不了趋势。**

### 4.2 背驰为何在放宽后依然不可靠

放宽为「重心移动计数」后，`ClassifyTrend` 接收的是**全时段所有中枢**，输出**一个全局方向**。但缠论的背驰本质是**局部趋势段的末端反转**：

- 上涨段末端 → 顶背驰 → 做空
- 下跌段末端 → 底背驰 → 做多

全局分类无法识别涨跌转折（RB 实际是 3100→6204 暴涨，再 6204→2912 暴跌），于是：

1. 全时段判 UP → 只发顶背驰做空信号，B1/B2 底背驰买点**永远测不到**
2. 做空长期上涨的品种 → 被反复止损 → 负 alpha

**结论**：背驰买卖点的验证，被「全局趋势分类」的方法论缺陷污染。要真正验证，需要把「全局分类」重构为「趋势分段识别」（涨段/跌段切分 + 每段末端背驰），这是对 spec §4.3/§5 核心方法论的改动，非微调。

---

## 5. 结论

1. **三买卖点（B3/S3）无 alpha，结论确凿**——两品种一致负，逻辑自洽。
2. **背驰买卖点（B1/B2/S1/S2）在当前 spec 框架下无法稳健验证**：
   - 严格趋势定义 → 背驰永远 = 0，从未触发
   - 放宽 → 全局单方向，B1/B2 仍测不到，S1/S2 负 alpha 且不稳健
3. 正确验证背驰需要**趋势分段重构**（改 spec 核心方法论），工程量大、性价比存疑，暂不做。

**最终判定**：缠论买卖点层（按 spec §5-§6 的全局趋势分类 + 背驰 + 三类买卖点实现）**无正 alpha**。

---

## 6. 后续建议

- **笔 + 中枢降级为辅助指标**：用于趋势过滤、择时、结构识别，而非独立交易信号。
- **不独立使用买卖点开仓**：B1/B2/B3/S1/S2/S3 作为方向提示，需叠加其他过滤（如大级别趋势、波动率、基本面）。
- **若未来重拾背驰**：需先解决「趋势分段」——识别局部涨跌段，再在段末端检测背驰，而非对全时段中枢做全局分类。
- **代码状态**：`ClassifyTrend` 的「重心计数放宽版」为实验性改动，验证后已回滚至 spec §4.3 原文，保持代码与知识库一致。
