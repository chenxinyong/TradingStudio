### 1.2 数据流时序示例

**时间线: 09:30:05.123**

```
T+0ms   CTP → OnQuote(IF2501, LastPrice=5000.0)
		│
T+2ms   └─→ CtpLiveFeed.merged.Writer.Write((IF2501, TickRecord, 20250120))
			│
T+3ms       ├─→ PersistChannel.Write() → CSV 落盘队列
			│
T+5ms       └─→ eventChannel.Writer.Write(TickEvent)
				│
T+8ms           └─→ TradingEngine.ProcessTick()
					│
					├─→ _tickSnapshot.Update(IF2501, 5000.0)
					├─→ _execution.ProcessTick() → 检查限价单触发
					│     └─→ 返回 Fill[] (假设有单子成交)
					│
					├─→ _strategies.DispatchTick()
					│     │
					│     └─→ MyStrategy.OnTick()
					│           └─→ ctx.PlaceOrder(IF2501, Buy, 1, 5001.0)
					│                 │
T+15ms              │                 └─→ ExecutionHandler.Submit()
					│                       └─→ SendToExchange() → CtpTraderBridge
					│                             └─→ TraderApi.InsertOrder()
					│
T+20ms              └─→ OrderOutbox.Writer.Write(OrderEvent) → SignalR 推送

T+150ms CTP → OnRtnTrade(OrderRef=123, Price=5001.0, Volume=1)
		│
T+152ms └─→ FillChannel.Writer.Write(Fill)
			│
T+155ms     └─→ fillReadTask 消费
				  │
				  ├─→ _portfolio.ProcessFill() → 更新持仓
				  ├─→ _strategies.DispatchOrderEvent() → 通知策略
				  └─→ OrderOutbox.Writer.Write() → SignalR 推送成交
```

### 2.2 K-way Merge 示例

**场景**: 同时回测 IF2501 + IC2501 + IH2501

```
数据源:
  IF2501: [Bar(09:31), Bar(09:32), Bar(09:33), ...]
  IC2501: [Bar(09:31), Bar(09:32), Bar(09:33), ...]
  IH2501: [Bar(09:31), Bar(09:32), Bar(09:33), ...]

K-way Merge 输出:
  T=09:31 → yield Bar(IF2501, 09:31)
		 → yield Bar(IC2501, 09:31)
		 → yield Bar(IH2501, 09:31)
  T=09:32 → yield Bar(IF2501, 09:32)
		 → yield Bar(IC2501, 09:32)
		 → yield Bar(IH2501, 09:32)
  ...

引擎消费:
  foreach (var barEvt in mergedStream)
	├─→ 09:31 IF → OnBar(IF2501)
	├─→ 09:31 IC → OnBar(IC2501)
	├─→ 09:31 IH → OnBar(IH2501)
	├─→ 09:32 IF → OnBar(IF2501)
	...
```

## 6. 故障排查检查清单

### 6.1 Live 模式无行情

```
检查清单:
□ appsettings.json → Live:MdFront 是否正确
□ appsettings.json → Live:UserId / Password 是否正确
□ 日志中是否有 "CTP login OK"
□ 日志中是否有 "Subscribe" 成功
□ SignalR 客户端是否连接 /hubs/engine
□ 防火墙是否拦截 CTP 端口
□ CTP 柜台是否在维护时段

日志示例 (正常):
[09:00:15] CTP: Connecting to tcp://...
[09:00:16] CTP login OK TradingDay=20250120
[09:00:17] CTP connected: tcp://...
[09:00:18] [INFO] Subscribed 80 instruments
```

### 6.2 Backtest 运行缓慢

```
检查清单:
□ 是否使用 --mode tick (Tick 模式更慢)
□ bars.db 文件大小 (> 10GB 考虑 DuckDB)
□ 是否查询了过长时间范围 (> 1年)
□ 是否同时回测 > 50 个品种
□ 硬盘是否为 HDD (推荐 SSD)

优化建议:
• 使用 DuckDB: --db bars.duckdb
• 缩小时间范围: --start 2025-01-01 --end 2025-03-31
• 减少品种数量: 修改 strategy.json → instruments
• 使用 Bar 模式: --mode bar (默认)
```

### 6.3 Collect 频繁重连

```
检查清单:
□ health.json → reconnects 计数是否持续增长
□ 日志中是否有 "OnFrontDisconnected"
□ 网络是否稳定 (ping CTP 服务器)
□ 是否在 CTP 维护时段 (周六全天)
□ 是否订阅了过多合约 (> 500)

日志示例 (异常):
[14:30:15] [WARN] CTP MdApi disconnected (0x2003)
[14:30:16] [WARN] Reconnect #1 in 2s
[14:30:18] CTP: Connecting to tcp://...

解决方案:
• 减少订阅数量: 使用 EXCHANGE / SYMBOL 过滤
• 检查网络质量: traceroute / mtr
• 联系券商: 确认账号未被限流
```
